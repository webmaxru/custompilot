Copilot usage metrics API · Changelog, Oct 22 2026

See which of your skills, agents and MCP servers developers actually use.

Copilot usage metrics now report the configured names of the skills, custom agents, MCP servers, slash commands and plugins your organization creates, instead of grouping them under other or custom. This demo simulates 28 days of reports for the fictional org contoso-eng, spanning the release.

Open the full insights dashboard →Explore trends, adoption, and actionable insights with simulated or real reports.

Named entries

totals_by_skill, totals_by_custom_agent, totals_by_mcp, totals_by_slash_cmd and totals_by_plugin show the configured name, not other / custom.

Up to 25 entries

Each list now holds up to 25 entries per record (up from 5). Remaining activity goes into a trailing other entry.

Unchanged counts

interaction_count and the distinct_*_use_count fields are calculated exactly as before.

Simulation. Every number on this page is generated in your browser by a deterministic simulator (64 developers, 5 teams, Oct 8 – Nov 4 2026). No real API is called. Names appear from report day Oct 22; earlier days use the September format.

7Analyze a report file

          
Drop a real NDJSON report from the API (aggregate 1-day, 28-day, or per-user) or load a simulated one. Files are parsed locally in your browser and never uploaded.

        

      

      

        
        

          
          
          
        

        

          How to get a real report file
          
From a local clone of this repository, run the following in PowerShell. You need Node.js 20+ and GitHub CLI (gh) signed in to an account with Copilot metrics access.

          
$env:GITHUB_TOKEN = gh auth token
node .\scripts\summarize.mjs --org YOUR_ORG --report organization-28-day --save .\copilot-report.ndjson

          
Replace YOUR_ORG with your organization's login, not your personal username. The organization's usage metrics policy must be enabled, and your token needs appropriate permissions (read:org for classic tokens). Organization owners and roles with View Copilot Metrics can access these reports.

          
This saves copilot-report.ndjson in the current folder. Click Choose a file above and select it. The script requests signed download links, downloads every report part, and saves the actual NDJSON. Do not upload the JSON response containing download_links.

          
For developer reach in the full insights dashboard, also download the matching per-user report and load both files together:

          
node .\scripts\summarize.mjs --org YOUR_ORG --report users-28-day --save .\copilot-users.ndjson

          
The aggregate 28-day report contains daily history. The per-user 28-day report contains period totals, not daily user history; reach is available only for its full reporting window. To analyze user reach over individual days, download users-1-day reports with --day YYYY-MM-DD. For enterprise reports, replace --org YOUR_ORG --report organization-28-day with --enterprise YOUR_ENTERPRISE --report enterprise-28-day and use a token with enterprise metrics access.

        

        

      

    


    

      
Good to know

      

        
Coverage
Names come from Copilot CLI (interactive and prompt mode), the GitHub Copilot app, ACP integrations such as JetBrains, and the Copilot SDK. Prompt mode, the app and ACP need CLI 1.0.97+; the SDK needs v1.0.21+. IDE built-in chat telemetry does not report names.

        
History
Names appear for report days processed after the release. Earlier days still show other or custom, as in the dashboard above.

        
Accuracy
Metrics come from client telemetry and can undercount (outdated clients, blocked telemetry). Use them for trends and adoption, not exact accounting.

        
Review before sharing
Names are reported as configured. Review them before sharing reports outside your organization.

        
Access
Enterprise owners, billing managers, organization owners, or a custom role with “View Copilot Metrics”. The Copilot usage metrics policy must be enabled.

        
Plugins ⊂ skills
Plugin totals count only plugin skill invocations, so they are already included in skill totals. Don't add the two together.
